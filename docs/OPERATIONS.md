# 数据、运营与发布说明

## 数据链路

代码总表与公开收益表构成发现入口，非监管名录。只解析JSON和HTML表格，不执行来源JavaScript。按6位代码去重，新份额写入，来源不再收录的旧份额保留并标“存续待核验”，不擅自判断退市。收益表的第一日期对应5/6列，字段结构、规模、日期倒退和年化异常均拒绝覆盖。每次成功保存市场来源SHA-256及抓取时间。

每轮抓取收益领先12个普通货币份额及已有渠道记录的天天基金规则；只有这一个渠道的公开页面证据。抓取这些份额和余额宝历史样本的首次最多5页、100条历史收益，之后增量合并并保留最近400个自然日；NAVTYPE必须为1。基金公司直销、银行、支付宝的渠道覆盖仍未完成，不外推规则。

每个来源失败保留对应旧快照，写入 `data/status.json`；市场失败仍构建包含失败状态的页面。独立文件以临时文件替换，读取及测试通过后构建；测试失败则不部署。每轮完整流程状态可查看Actions，页面同时展示抓取日期与披露日期。历史请求仅提供有限窗口，更长区间缺失即拒算。

注意：页面仅在加载时按上海日期检查时效；保持页面跨天打开应刷新。GitHub定时任务不是准点服务，UTC00:23对应北京时间08:23；公共仓库60天不活跃可能停用计划任务，维护者需监控运行。没有账号凭据、付费API或私有数据。

## 发布与回滚

GitHub Pages继续使用原仓库原网址。定时和手动Actions：刷新→Python/Node验证→H5构建→保存数据/状态→上传Pages artifact→部署。需Pages来源设为GitHub Actions，工作流拥有contents:write、pages:write、id-token:write，环境为github-pages。

首次通过浏览器上传源码包时，工作流可在src不存在时展开 `source-package.zip`，随后将完整源码保存到主分支；之后直接编辑src，不能靠上传旧源码包覆盖维护源。根index.html为静态发布后备，正式Actions部署仅上传dist。

回滚：在仓库恢复已验证提交或revert变更，然后运行工作流；不要删除原工程。最早已发布旧版提交为c1339d1。数据源失败应保留失败状态而不是把旧快照标成今天收益。连续失败检查接口结构、数据许可、平台网络、Actions权限和计划停用，不能通过关闭TLS验证解决。

## 产品验收

金额与周期矩阵、候选/基准利率、升降情景、等待天数、额外费用、鸡腿目标均可调整。显示正负收益差；基准选择明确标为历史接入样本。手机榜单与高级矩阵使用纵向卡片，目录列表窄屏改为卡片，详情键盘可关闭；无外部字体或追踪脚本。

真实手机微信内置浏览器及中国大陆不同网络尚需用户设备实测，不能以桌面模拟替代。GitHub.io在部分网络可能不可达；域名与境内托管需要实际账号/费用时另行处理。

## 业务边界

本站是公开资料观察工具；没有销售、交易、开户或个人持仓读取。条件候选只反映有限公开规则，不构成对具体用户的最优推荐。普通赎回确认日不是银行到账日。货币基金不是存款，不保证本金收益。

第三方公开访问不等于再分发授权。未取得监管认可、销售资质或数据许可审核结论；商业推广与持续公开使用前，维护者应完成来源许可、基金信息服务及推荐业务边界、广告/平台规则的专业审核。不得把覆盖率解释成全市场完整率，也不得把余额宝历史样本最高解释成当前平台最高。

官方工程依据：https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule ；https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages 。


## 2026-10-26 实测问题修复

所有页面通过同一份额解析器使用行情。原始收益表缺同日完整字段时，仅允许回退至NAVTYPE=1且披露日相同、年化与万份收益均完整的历史记录；来源、抓取日期、回退原因随记录进入资料库、详情和结果卡。不以不同日期记录补当前日。原始覆盖和含回退的解析覆盖分别展示。

缺行情时利率为空，必须明确选择手动假设并填写；修改带入值即转为用户修改。结果卡同时保存双方完整名称、代码、参考日期、实际利率依据和情景调整标识，不能把用户假设写成行情。

筛选与主计算器共享本金、周期和取用需求；候选可一键带入，金额/周期可双向同步。高级矩阵独立折叠且不改变主情境。研究性试算保留条件不符的份额，但主结果和矩阵每一金额都显示门槛、限额冲突或取用未知；筛选的排除记录默认折叠、明确非候选。

历史回放预检双方共同日期，预选最新连续完整区间（至多7天），没有共同日期时禁用回放按钮，并展示双方可用日期及近7日缺口。任何用户修改区间仍执行完整性校验。

健康状态拆分获取失败、口径排除、沿用旧值、记录缺失；仅获取失败进入failures，口径排除进入qualityExclusions，原抓取日期保存在retained，近7日具体缺日进入missingRecords。旧格式的质量排除在前端兼容分类，不冒充网络故障。


## 新版比较流程与数据维护

首页只保留金额、周期与取用需求，主入口为开始比较。候选按完整历史覆盖、共同日期覆盖、规则抓取时间排序，收益率仅作后续排序依据，不生成综合评分。到银行卡、快赎或支付证据不足时没有已确认候选，可主动改为仅研究公开门槛；不能自动放宽条件。

近30／90日累计逐个自然日求和，缺一天即不展示累计。当前年化维持的未来试算单独标为假设。历史接口仅接纳NAVTYPE=1；合并区间清除对应日记录而不拆分。逐页URL、抓取时间和SHA-256随历史快照保存。总历史补抓预算480秒、四个并发请求，来源失败保留各自旧数据。

官方资料入口存放于data/official.json，当前仅覆盖7个经核验份额；历史公告标发布日期，链接核验日不冒充资料更新日。官方材料仅供查阅，不替代当前行情或销售渠道规则。新增映射必须先阅读原文确认份额代码。

条件与匿名流程计数保存在本机sessionStorage，条件在下次读取时清理超过24小时未使用的记录；清除条件会删除本站相关键。分享需主动生成链接，参数放URL片段；别人打开时利率按自定义假设恢复，日期与免责声明随结果显示。反馈仅生成本地文本，由用户自行提交；不自动发送持仓、金额或联系方式。流程计数只用于本机会话验收，不是全站分析。


## 2026-10-26 公开取用规则补齐

已移除bank/ordinary/wallet/pay无条件“资格未验证”的排除。筛选仅依据公开产品与渠道规则；个人账户状态、剩余额度、绑卡状态不进入判断，也不作为展示给用户的待核实理由。

新增scripts/import_liquidity.py与data/liquidity.json：读取官方活期宝关联清单（当前50份额），逐个获取销售规则，并分别核验普通取现、快速取现、极速回活期宝、基金支付与消费支付的来源。每份原文保留URL、校验日期、SHA-256；来源文字关键条件改变或获取失败时，对应规则停止自动确认，保留旧记录与错误，不将失败记录重新标为已更新。每日任务自动重新抓取。

银行卡快取只用于官方关联清单内份额；整笔本金需不超过单只基金每日1万元上限，7×24小时受理，通常当天到账，“最快1秒”不作为保证。普通取现采用官方较宽的T+1至T+2工作日窗口，15:00为交易日切点。活期宝充值起点来自关联清单，与基金普通申购入口门槛分开，不把两条入口混为一谈；申购上限仍须有同份额天天基金公开页。

极速回活期宝按该份额公开支持标记判断，T+1充值确认。官方question_834与question_646对T+1日20点前/后可取现表述不一致，保留两处来源与差异；只确认回款功能，不视为银行卡当天可用，安排取现按不早于T+2规划。

基金支付与日常商户消费分开。天天基金公开业务说明确认的是用活期宝买基金，不能据此推断支持商户消费；消费需求无合格替代时显示具体业务范围，并提供支付宝官方余额宝消费说明，不声称市场不存在其他产品。

收益表可能先更新当天空表头：解析器在两个带日期列中选取最近含实际完整收益的一列，记录真正披露日、最新表头日及选择原因。两列皆空则拒绝覆盖有效快照；不能把未披露的当天当作有行情，也不能将前日数值标成今日。
